# Swift architecture gate

The repository checks its architecture rules with one command. Run it before every commit and fix what it reports. The repository's `AGENTS.md` and `Docs/ARCHITECTURE.md` hold the full rules and their reasons; read them when a finding is unclear.

## Commands

| When | Command |
| --- | --- |
| Before committing | `python3 -I scripts/gate/gate.py` (whole working tree) or `--staged` (staged changes only) |
| Once per checkout | `sh scripts/install-git-hooks.sh` (pre-commit, commit-msg, pre-push) — only when the user asks; it writes `.git/config` |
| Check a branch before a pull request | `python3 -I scripts/gate/gate.py --range origin/main..HEAD --commits origin/main..HEAD` |
| After violations went down | `python3 -I scripts/gate/gate.py --update-baseline`, commit the tightened baselines with the code |
| What the rules are | `--list-rules`; `--self-test` checks the gate itself |

Project paths, thresholds and severities live in `scripts/gate/gate.config.json`; baselines in `scripts/gate/baselines/` (and any baseline the config names). `SKIPPED <rule>` means a tool was missing on this machine; say so in your report as "not verified", never as "passed".

## The rules in brief

1. **File size.** A new Swift file stays at or below the limit (1,000 lines). A file already above it is in the baseline and may only get shorter.
2. **`@Observable` class bodies** hold only instance stored properties, designated initializers and `deinit` (plus what Swift forbids in extensions: `override`, `required init`). Methods, computed properties, nested types, type aliases, static properties and convenience initializers go into an `extension` right after the class in the same file. Each body member costs macro-expansion time in every compile job that uses the class.
3. **No library-sized collections in memory.** No new whole-library arrays, dictionaries or id sets as stored properties; read through the catalog interfaces (by id, by page, counts, streaming). SQL for the catalog tables lives only in the catalog directory. Bounded exceptions carry a same-line comment with the bound and the reason, in the format the finding shows.
4. **Layering.** The core Swift package imports no UI framework (SwiftUI, UIKit, AppKit). Dependencies point down: UI → services → core package.
5. **Layout.** Core-package sources sit in domain subdirectories, never in the package root; a test file's directory mirrors the source directory it tests.
6. **Generated Xcode project.** `project.pbxproj` is generated by XcodeGen from `project.yml`. Adding, deleting or moving a Swift file means regenerating on the build Mac with the pinned XcodeGen version. Prefer folder sources in `project.yml` over per-file lists.
7. **Localization.** Every key exists in every language file of a group, with the same format specifiers as the development language; no empty values.
8. **Tests travel with code.** A commit that touches only tests is refused; put the test in the commit of the code it covers.
9. **Commit message.** One line saying what changed for the user or the app, in the repository's language and style (see `git log --format=%s -30`); optionally one short sentence after a blank line; `refs #NNN` when there is an issue. Verification evidence goes into handoff notes, not the commit.
10. **No AI attribution** in commits, pull requests, code comments or release notes: no `Co-Authored-By` naming an AI, no "Generated with …", no session links or trailers, no robot emoji. Naming a product as part of a feature ("call the Claude API") is fine.
11. **Baselines only shrink.** Existing violations are counted per file (per class for `@Observable`); new code may not add to them.

## Fixing findings

| Finding | Fix |
| --- | --- |
| `file-size` new file too long | Split by responsibility: one type family per file, large types' extensions in `Type+Responsibility.swift`. |
| `file-size` baselined file grew | Put the new code in a new file, or move a part out first. |
| `observable-class-body` | Move the listed members verbatim into `extension TypeName { }` directly after the class; move `#if` members together with their own `#if`. Pure move, no edits in the same commit. |
| `library-scale` | Use the catalog reader / row lists / paged queries instead of whole-library arrays; follow the rule text in the finding. |
| `layering` | Keep the UI-dependent part in the app module; give the core package platform-neutral types. |
| `kit-layout` | Move the file into the matching domain directory; tests mirror the source path. |
| `project-file` | Regenerate the project with XcodeGen on the build Mac; if the file should not be in that target, change `project.yml`, then regenerate. |
| `localization` | Add the key to every language with matching specifiers (`%@`, `%lld`, positional `%1$@` allowed). |
| `baseline-integrity` | Revert the baseline change and fix the code. |
| `tests-with-code` | Fold the test into the related code commit. The override environment variable named in the finding is for the owner's rare exceptions only. |
| `commit-message` | Rewrite the message (`git commit --amend`, or `git rebase -i` for older commits before pushing). |

If a finding looks wrong (a false positive), report it with the file and line instead of working around it.

## Never

- Never loosen a baseline, raise a threshold, change a rule to `warn` or disable it to get a commit through. Loosening is the repository owner's decision (`--update-baseline --allow-growth "reason"` on the main branch).
- Never skip hooks with `git commit --no-verify` or `git push --no-verify`.
- Never hand-edit `project.pbxproj`.
- Never commit only tests, and never add AI attribution anywhere.
- Never edit the gate itself (`scripts/gate/`) as part of an unrelated change.
